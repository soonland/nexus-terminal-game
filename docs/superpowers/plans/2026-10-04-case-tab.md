# CASE Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the NOTES tab with CASE: a casebook of the people the player has met, a timeline, and the accounts, nodes and files they already had, each item shown once and tied to the document it came from.

**Architecture:** Authored data in `src/data/casebook.ts` (people and facts, each fact with a source and a verbatim quote). A pure `buildCasebook(state)` in `src/engine/casebook.ts` derives everything from `filesRead`, obtained credentials, employees and nodes (no new saved state). A `CasePane` component renders collapsible sections and replaces `NotesModal`; sources link into the explorer selection.

**Tech Stack:** TypeScript, React, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-04-case-tab-design.md`

## Global Constraints

- No `SAVE_VERSION` change and no new saved state: the casebook is derived.
- Naming rule: no authored string matches `/aria/i`; the casebook never says a person is a suspect, guilty, a mole or a traitor.
- Credentials are shown with their password and access level and **never** with where they work (`validOnNodes`) or where they were found (`source`); no rendered credential line contains a node id, IP, label or `source` text.
- Employee `traits` are never rendered.
- Every credential, node and file is shown once. A credential that belongs to a person is on their card, otherwise under ACCOUNTS.
- Excluded on purpose: O.R. (the player's own handler), the AI and Sentinel (not people).
- No `console.*`; arrow functions; semicolons; single quotes.
- Before each commit: `pnpm format`, `pnpm tsc -b`, `pnpm lint`, `pnpm test:coverage`, `pnpm knip` (add no findings). Commits are conventional, subject starts lowercase, and end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Nothing is pushed and no PR is opened without the user asking.

## Rulings (flagged for review)

- **Sections:** PEOPLE, TIMELINE, ACCOUNTS, NODES, FILES; PEOPLE open by default; open state is session-only.
- **People order:** story characters in the order the player first unlocked a fact of theirs (derived from the order of `filesRead`), then account holders alphabetically.
- **`ceo.root` belongs to Hale**, `j.mercer` to Mercer, `e.torres` to Torres. `a.walsh` has no story entry, so it stays under ACCOUNTS.
- **A source is a link only when the file can be opened:** it is on the current node, or an exfiltrated copy exists; otherwise it is plain text with the node's label.
- **Unread dot** on the aux pane when new casebook items arrive while the CASE tab is not showing; a resumed run starts read (reuses `useUnread`).
- **Partial dates** (`YYYY-MM-DD`, optionally ` HH:MM`) sort lexicographically.

## Review Focus

- A document unlocking two people's facts at once, and one person reached only through a credential (no facts) — Task 1.
- Reading a file twice, or reading an exfiltrated copy only (`cat local:`) — the unlock keys on `filesRead` (node and path), so a local read must not unlock — Task 1.
- A save and load rebuild the same casebook — Task 1.
- The password is shown but the card/ACCOUNTS line never reveals where it works — Tasks 1–2.
- Pre-reveal text: the board vote mentions the secret name, so the vote's facts must be worded without it — Task 1.
- Narrow screens: the aux pane is one pane at a time; the unread dot must show on the tab — Task 2.
- A fact whose source document later changes: the verbatim `quote` test fails the build — Task 1.

### Task 1: Authored data and the casebook engine

**Files:**
- Create: `src/data/casebook.ts`, `src/engine/casebook.ts`
- Test: `src/data/__tests__/casebook.test.ts`, `src/engine/casebook.test.ts`

**Interfaces:**
- Produces:
  - `interface CasePerson { id: string; name: string; role: string; credentialIds?: string[] }`
  - `interface CaseFact { id: string; person: string | null; text: string; title?: string; date?: string; source: { nodeId: string; path: string }; quote: string }`
  - `CASE_PEOPLE: readonly CasePerson[]`, `CASE_FACTS: readonly CaseFact[]`
  - `interface CaseAccount { username: string; password: string; accessLevel: AccessLevel }`
  - `interface CasePersonCard { id: string; kind: 'story' | 'holder'; name: string; role: string; facts: CaseFact[]; account: CaseAccount | null }`
  - `interface CaseTimelineEntry { date: string; subject: string | null; subjectName: string | null; title: string; factId: string }`
  - `interface Casebook { people: CasePersonCard[]; timeline: CaseTimelineEntry[]; accounts: CaseAccount[] }` and `buildCasebook(state: GameState): Casebook`.
- Consumes: `fileReadKey`, `GameState` from `../types/game`; `Employee` (`state.employees`); `DIVISION` labels if available (else the raw `divisionId`).
