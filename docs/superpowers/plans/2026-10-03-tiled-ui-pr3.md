# Tiled UI PR 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the tiled UI (#229): a scripted Nexus line with unread markers, the trace meter on the COMMS pane, an ARIA/CASSANDRA tab for her replies, and a visual polish pass.

**Architecture:** The Nexus line is pure derived state. `src/data/nexusMessages.ts` holds the authored messages; `src/engine/nexusLine.ts` decides which are due and latches them into `flags['NEXUS_MSG_<id>']` inside `withTurn`, so the UI renders `receivedNexusMessages(state)` and a reload shows exactly the same list. Aria's dialogue stops being terminal output: `cmdAriaAI` returns the reply separately (`ariaReply`) and the ARIA tab renders it from `state.aria.messageHistory` (so it survives a reload).

**Tech Stack:** TypeScript, React, Vitest, Playwright (screenshots).

**Spec:** `docs/superpowers/specs/2026-10-03-tiled-ui-design.md` (sections *COMMS pane*, *Nexus line*, *Trace meter*).

## Global Constraints

- No `SAVE_VERSION` change. Persisted data is only `flags['NEXUS_MSG_*']` plus existing state.
- Naming rule: no Nexus text contains "aria" or "cassandra" (nor "sentinel"); the ARIA tab label is `CASSANDRA` until `ARIA_NAME_KNOWN`, then `ARIA`.
- Rhee is signed only as `O.R.` (bible §5/§6); Nexus is receive-only: no input, no AI.
- Sentinel's interruption still cuts into the Nexus line.
- Reduced motion: no flicker animation (`prefers-reduced-motion`).
- No `console.*`; arrow functions; semicolons; single quotes.
- Before each commit: `pnpm format`, `pnpm tsc -b`, `pnpm lint`, `pnpm test:coverage`, `pnpm knip` (add no findings). Commits are conventional, subject starts lowercase, and end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Nothing is pushed and no PR is opened without the user asking.

## Rulings (made without the user present; flagged for review)

- **Nexus order is definition order**, live and on reload (flags carry no sequence). The messages are authored so that order reads naturally.
- **`mission_start` is always "received"** (no latch needed), so the line has a message the moment the game starts.
- **Threshold messages latch** into flags, so a burn (which clears `threshold_*` flags) never re-sends or removes them.
- **`layer_3` / `layer_4` fire from the current node's layer**, not from `layer_N_reached` flags (those only exist from layer 3 up, for Sentinel).
- **The ARIA tab is read-only.** Replies come in; the player still types `msg …` (or plain text on layer 5) in the terminal. Favor offers (the "type yes/no" block) stay in the terminal because they are a prompt the terminal must answer.
- **Unread**: a new Nexus message or Aria reply while COMMS is not the focused pane marks the pane title and the status bar. A resumed game starts with everything read; a new game (turn 0) starts with the opening message unread.
- **The trace readout leaves the terminal header** (spec) and becomes a meter on COMMS's top edge; the status bar still shows the number.

## Review Focus

- A burn clears threshold flags: Nexus messages must neither repeat nor vanish — Task 1.
- Reload mid-run: the Nexus list and the ARIA tab rebuild identically from saved state — Tasks 1 and 3.
- A new run (new game, burn retry, resume choice) must not leak the previous run's unread state or ARIA lines — Tasks 2 and 3.
- Narrow screens (one pane at a time): unread markers must show on the pane tab strip — Task 2.
- Aria replies must never appear in the terminal twice (no double render) while offers still do — Task 3.
- Reduced-motion users get no flicker — Task 4.
